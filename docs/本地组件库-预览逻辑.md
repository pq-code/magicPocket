# 本地组件库 - 组件预览逻辑

## 数据流

1. **componentLibrary.vue**  
   用户从左侧文件树选择组件 → `selectedComponent` 为当前选中的 `ComponentMeta`。

2. **ComponentSandbox**  
   接收 `component`，构造预览用节点并交给渲染引擎：
   - `previewNode` = `{ type, key, componentName, props, children: [], npm }`（与画布节点结构一致）
   - 调用 `TypeRenderEngine(previewNode, [])` 得到 VNode。

3. **TypeRenderEngine**  
   按顺序决定用谁渲染：
   - **1）componentGenerators[item.type]**  
     若存在对应生成器（如 `Form`、`container`、`CodeHighlight`、`Table`、`input` 等），直接用内置/项目内组件渲染。
   - **2）builtin 且未注册**  
     若 `sourceType === 'builtin'` 且没有生成器 → 渲染「未知组件」占位。
   - **3）getAsyncComponent(npm)**  
     其余情况按 `npm` 动态加载（如 element-plus、npm.component 路径等）。

## 为何可能“预览不显示”

1. **type 与生成器 key 不一致**  
   - 物料里 Table 的 `type` 是 `"table"`，生成器 key 是 `"Table"`，会走动态加载而非内置 Table，可能表现异常。  
   - 处理：在 TypeRenderEngine 里对 `table` 做别名，映射到 Table 生成器。

2. **异步组件未包在 Suspense**  
   - Form、CodeHighlight、Table 等是 `defineAsyncComponent`，加载完成前可能不渲染内容。  
   - 处理：在 ComponentSandbox 里用 `<Suspense>` 包住 `TypeRenderEngine` 的返回值，并提供 fallback（如“加载中”）。

3. **Element Plus 组件用法不对**  
   - 如 Backtop 需要 `target` 等 props，当前只传了 `item/children`，可能渲染空白或报错。  
   - 处理：对已知的 element-plus 组件在生成器里写死正确 props，或单独写一层包装。

4. **仅 meta 的包没有 localPath**  
   - 仅 meta.ts/index.ts 的包没有入口文件，`npm.localPath` 为空，若走动态加载会失败。  
   - 处理：这类组件尽量在 componentGenerators 里按 type 注册（如 Backtop、Button），或用 element-plus 生成器统一处理。

## 小结

预览 = **ComponentSandbox 用 ComponentMeta 造 previewNode → TypeRenderEngine 按 type/npm 选生成器或动态加载 → 渲染出 VNode**。  
不显示时重点查：type 是否在 componentGenerators、是否为异步组件（需 Suspense）、Element 组件是否缺必要 props。
