# 组件库与物料库说明

## 设计约定（推荐）

- **物料库**：只拉「已上架」的物料（来自 DB/发布服务）；未发布的组件不会出现在低代码左侧列表。
- **组件库**：预览与渲染使用**本地组件**（沙箱用本地 meta + 本地加载），不依赖已发布版本。
- **组件库 meta**：使用 **Agent** 按协议生成与维护。
- **在低代码中使用组件**：必须先**发布**，发布后物料上架，才能在物料库中展示并被拖拽到画布。

这样组件库（开发/编辑/预览）与物料库（已发布/可拖拽）边界清晰，生产环境物料可审计、可版本化。

---

## 1. 概念区分

| 概念 | 含义 | 数据形态 |
|------|------|----------|
| **组件库** | 本地可编辑的组件代码仓库；可编辑文件、用 Agent 生成 meta、可打包发布到 npm；**预览用本地组件** | 文件系统目录，扫描得到 `ComponentMeta[]`；沙箱用本地加载渲染 |
| **物料库** | 低代码左侧「可拖拽的组件列表」的数据源；**只展示已上架物料** | 来自 DB/发布服务的「已上架」列表（或当前实现的静态 + 本地合并，见下） |

- **组件库**：偏「开发/编辑/发布」—— 写代码、Agent 生成/维护 meta、本地预览、打包发布。
- **物料库**：偏「低代码使用」—— 只拉已上架物料，画布侧仅能拖拽已发布的组件。

三者关系简述：

- **组件库** 与 **渲染器、编辑器** 互相独立。
- **物料库** 数据来源 = 已上架物料（DB/发布服务）；组件要在低代码中使用必须先发布。
- **组件库内预览**：不依赖发布，直接用本地组件 + 本地 meta 在沙箱中渲染。

---

## 2. 物料库数据从哪获取？

**目标设计**：物料库只拉「已上架」的物料（DB 或发布服务 API），不混入未发布的本地组件。

**当前实现**（`materialArea.ts`，可后续改为只读已上架）：

1. **静态物料**：`packages/material.ts` 的 `materialComponents`（来自各 `packages/[Component]/meta.ts`）。
2. **本地组件库**（可选）：主进程扫描「组件库目录」得到 `ComponentMeta[]`，写入 `useLocalLibraryStore().localLibraryComponents`。

合并规则（当前）：`componentList` = 静态 + 本地按 `type` 合并。**演进后**：物料库数据源改为只拉已上架列表，不再把本地未发布组件并入物料库。

---

## 3. 怎样的 meta 才算「可用的 meta」？

在**渲染器**里，要能根据 meta 解析并加载组件，需要满足：

1. **必有字段**  
   - `type`：字符串，画布节点类型，与注册表 / 节点 `type` 一致。

2. **加载依据（二选一即可）**  
   - 节点上带 `npm`（拖入画布时从物料 meta 带下来），或  
   - 应用启动时通过 `registerFromMetaList` 把该 `type` 注册到 `ComponentRegistry`。

3. **`npm` 至少能解析出一种加载方式**（参见 `NodeNpmInfo` 与 `resolveSourceType`）：  
   - `component`：项目内路径（如 `packages/Form/src/Form.jsx`），对应 **local**  
   - `localPath`：本地文件系统绝对路径（Electron 下组件库目录内文件），对应 **localFs**  
   - `package`：npm 包名（如 `element-plus`），对应 **npm**  
   - `url`：远程 ESM/UMD，对应 **remote**

**用于物料库展示**时，建议还有：

- `componentName`：中文名，左侧列表展示。  
- `group`：分组，左侧折叠分组。

总结：**可用的 meta = 有 `type` + 有可解析的 `npm`（或该 type 已注册）**；若要在画布中正确渲染，拖入的节点需要带上 meta 的 `npm`（当前拖拽时整条物料会放进 `pageJSON.children`，因此会带上）。

---

## 4. 组件库预览 vs 低代码使用

| 场景 | 数据来源 | 渲染方式 |
|------|----------|----------|
| **组件库内预览** | 本地扫描的 meta（或本地文件中的 meta），Agent 可生成/更新 | 沙箱用**本地组件**加载（如 `localPath` / 项目内路径），不依赖发布 |
| **低代码画布使用** | 仅**已上架**物料（DB/发布服务） | 渲染器用节点上的 `npm`（来自物料记录）或注册表解析加载 |

- **组件想在低代码中使用 → 必须先发布**，发布后上架，物料库才展示，用户才能拖拽到画布。
- **组件库内**：编辑代码、Agent 生成 meta、本地预览；无需发布即可看到效果。

---

## 5. 流程小结

```
组件库（本地）
    → 编辑文件、Agent 生成 meta
    → 主进程扫描 → ComponentMeta[]（供组件库内文件树 + 沙箱预览）
    → 沙箱预览：用本地 meta + 本地加载渲染（不依赖发布）

发布
    → 组件打包/上传 → 物料上架（写入 DB 或发布服务）

物料库（低代码左侧）
    → 只拉「已上架」物料 → componentList
    → 不展示未发布组件

画布拖拽
    → 从 componentList 拖入的项（含 type、npm 等）作为节点加入 pageJSON
    → 渲染器：item.npm ?? getComponentNpm(item.type) → 加载并渲染
```

- **meta 可用性**：有 `type`，且 `npm` 能解析出 local/localFs/npm/remote 之一（或 type 已注册）。
- **物料库**：只拉已上架；**组件库预览**用本地组件，**低代码使用**需先发布。
