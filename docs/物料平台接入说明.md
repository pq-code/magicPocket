# 物料平台接入说明

## 概述

物料平台（Material Platform）是一个独立的后端服务，用于管理低代码平台的组件物料。本文档说明如何配置和使用物料平台。

## 后端配置

### 接口地址

默认地址：`http://127.0.0.1:3001`

可在 `src/renderer/src/api/apis/materials.ts` 中修改：

```typescript
const MATERIAL_PLATFORM_BASE = 'http://127.0.0.1:3001'
```

### API 端点

#### 认证相关

- `POST /api/auth/login` - 登录，返回 JWT token
- `POST /api/auth/logout` - 注销
- `POST /api/auth/register` - 注册（可选）

登录请求示例：
```json
{
  "userId": "admin",
  "password": "admin123445"
}
```

登录响应示例：
```json
{
  "code": 0,
  "result": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
  }
}
```

#### 物料管理

- `GET /api/materials` - 获取物料列表（支持分页、搜索）
- `GET /api/materials/:materialId` - 获取单个物料详情
- `POST /api/materials` - 创建物料
- `PATCH /api/materials/:materialId` - 更新物料
- `DELETE /api/materials/:materialId` - 删除物料

查询参数：
- `page`: 页码（默认 1）
- `pageSize`: 每页条数（默认 200）
- `group`: 按分组筛选
- `search`: 关键字搜索
- `createdBy`: 按创建者筛选

## 前端实现

### 自动登录流程

应用启动时会自动执行以下流程：

1. 检查 sessionStorage 中是否有有效的 token
2. 如果有 token，直接调用 `/api/materials` 获取物料列表
3. 如果没有 token，先调用 `/api/auth/login` 登录（使用默认账号）
4. 登录成功后获取物料列表
5. 如果物料平台不可用，降级使用静态物料

### 数据流

```
物料平台接口
    ↓
useMaterialsStore (Pinia Store)
    ↓
materialArea.ts (computed 响应式)
    ↓
draggingDraggingL.jsx (左侧组件库)
    ↓
用户拖拽到画布
```

### 核心文件

1. **API 层**：`src/renderer/src/api/apis/materials.ts`
   - 封装所有物料平台 HTTP 请求
   - 自动携带 token（通过 axios 拦截器）

2. **Store 层**：`src/renderer/src/stores/materials/useMaterialsStore.ts`
   - 管理物料列表状态
   - 提供登录、刷新、注销等方法

3. **数据源层**：`src/renderer/src/components/materialArea/materialArea.ts`
   - 合并物料平台、静态物料、本地组件库
   - 优先使用物料平台数据

4. **UI 层**：`src/renderer/src/views/draggingDragging/components/draggingDraggingL.jsx`
   - 显示组件库列表
   - 显示加载状态和数据来源

### 物料数据结构

物料必须符合 `ComponentMeta` 接口：

```typescript
interface ComponentMeta {
  type: string              // 组件类型（唯一标识）
  componentName: string     // 组件显示名称
  group: string            // 分组名称
  icon?: string            // 图标类名
  npm: NodeNpmInfo         // npm 加载配置
  props?: any              // 默认属性
  children?: any[]         // 子节点
}

interface NodeNpmInfo {
  exportName: string       // 导出名称
  package?: string         // npm 包名（如 'element-plus'）
  component?: string       // 本地组件路径（如 'packages/Form/src/Form.jsx'）
  destructuring: boolean   // 是否解构导入
  sourceType?: 'npm' | 'local' | 'remote' | 'localFs'
}
```

**重要**：npm 配置规则
- npm 包组件：只需 `package` + `exportName` + `destructuring`
- 本地组件：只需 `component` + `exportName` + `destructuring`
- **不要同时指定 `package` 和 `component`**，会导致加载失败

### 示例物料配置

Element Plus 组件：
```json
{
  "type": "Button",
  "componentName": "按钮",
  "group": "Element",
  "icon": "icon-anniu",
  "npm": {
    "exportName": "ElButton",
    "package": "element-plus",
    "destructuring": true
  },
  "props": {}
}
```

本地组件：
```json
{
  "type": "Form",
  "componentName": "表单",
  "group": "基础组件",
  "icon": "icon-dingdan",
  "npm": {
    "exportName": "Form",
    "component": "packages/Form/src/Form.jsx",
    "destructuring": true
  },
  "props": {}
}
```

## 状态显示

左侧组件库标题会显示当前数据来源：

- **加载中...** - 正在从物料平台拉取
- **(物料平台)** - 使用物料平台数据（绿色）
- **(静态物料)** - 物料平台不可用，使用静态数据（红色）

## 调试

### 查看 token

打开浏览器开发者工具 → Application → Session Storage → `materialPlatformToken`

### 手动刷新物料

```javascript
// 在浏览器控制台执行
const materialsStore = useMaterialsStore()
await materialsStore.refreshList()
```

### 手动注销

```javascript
const materialsStore = useMaterialsStore()
await materialsStore.logout()
```

### 查看物料列表

```javascript
const materialsStore = useMaterialsStore()
console.log(materialsStore.list)
```

## 降级策略

如果物料平台不可用（网络错误、服务未启动等），应用会自动降级到静态物料模式：

1. 使用 `packages/material.ts` 中定义的静态物料
2. 合并本地组件库扫描结果
3. 用户可以继续使用低代码编辑器，只是组件列表是静态的

## 已知问题修复

### ✅ 组件拖拽后无法渲染

**问题**：部分组件的 meta 配置中同时包含 `package` 和 `component` 字段，导致被错误识别为 `local` 类型。

**修复**：移除 Element Plus 组件 meta 中多余的 `component` 字段，只保留 `package` 字段。

涉及文件：
- Button/meta.ts
- PageHeader/meta.ts
- Search/meta.ts
- Breadcrumb/meta.ts
- Backtop/meta.ts
- Carousel/meta.ts
- Divider/meta.ts
- Image/meta.ts
- Form/meta.ts

### ✅ 拖拽克隆时缺少 key

**问题**：VueDraggable 默认克隆函数不会生成 key，导致 Vue 渲染异常。

**修复**：在 `componentContainer.jsx` 中添加自定义 `clone` 函数，确保克隆的组件包含唯一的 key。
