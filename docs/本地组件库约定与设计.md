# 本地组件库约定与设计

## 一、与当前 packages 的约定对齐

### 1. 项目内 packages 结构（参考）

```
src/renderer/src/packages/
├── index.ts                 # 组件库注册用（Vue install），Electron 不关心
├── Form/
│   ├── index.ts             # 单组件注册
│   ├── src/
│   │   ├── Form.jsx         # 组件入口
│   │   └── FormOperatorPanel.jsx
│   ├── components/          # 子组件
│   └── style/
├── DlockContainer/
│   ├── src/
│   │   ├── DlockContainer.jsx
│   │   └── ...
│   └── style/
├── Table/
│   ├── src/Table.jsx
│   └── ...
```

- **根 index**：只用于在渲染进程里 `import` 注册组件，本地组件库功能不依赖它。
- **每个组件**：一个子文件夹，入口可能是根目录的 `index.vue/jsx` 或 `src/ComponentName.jsx`。
- **组件描述**：当前项目里描述在 `materialArea/components/Form.ts` 等，是代码形式；本地选目录的组件库我们约定用 **meta.ts**，与 packages 内各组件的 meta.ts 概念统一。

### 2. 本地组件库目录约定（与 packages 一致）

用户选择的「组件库根目录」等价于上面的 `packages` 目录：

- **每个子文件夹** = 一个组件（如 `MyButton`、`Form`）。
- **组件入口**（任选其一即可视为有组件）：
  - 根目录：`index.vue` / `index.jsx` / `index.tsx` / `index.js`
  - 或 `src/组件名.jsx`（如 `src/Form.jsx`），与现有 packages 一致。
- **组件描述**：该组件文件夹下的 `meta.ts`，字段与协议一致（type、componentName、group、props 等）。
- **不要求**根目录有 `index.ts` 等注册文件；Electron 只做「扫描 + 展示 + 编辑描述/源码」。

## 二、选择目录后的行为

1. **自动分析**：递归/遍历所选目录的**直接子文件夹**（不要求再套一层 packages）。
2. **识别组件**：对每个子文件夹，若存在「入口文件」则视为一个组件：
   - 根目录 `index.vue` / `index.jsx` / `index.tsx` / `index.js`
   - 或 `src/<FolderName>.jsx`（如 `Form/src/Form.jsx`）。
3. **组件列表展示**：每个识别到的组件在左侧列表展示（名称、类型、分组等）；若该组件目录下存在 `meta.ts`，则用其填充展示；若**没有** `meta.ts`，仍展示该组件，但标记「未配置描述」。
4. **缺少描述文件时**：在扫描完成后，若存在「有入口但无 meta.ts」的组件，**弹窗询问**：「以下组件缺少描述文件，是否为其自动生成 meta.ts？」列出组件名，用户选「生成」则对每个缺失的组件生成默认 `meta.ts`（type、componentName、group、npm 等），写回磁盘。

## 三、组件描述 meta.ts 文件

- **文件名**：`meta.ts`。
- **位置**：组件文件夹根目录，例如 `MyButton/meta.ts`。
- **内容**：JSON 格式，符合 `docs/specs/component-descriptor.md` 与 `ComponentMeta` 类型（type、componentName、icon、group、npm、props 等）。  
- **npm**：本地组件库场景下可由扫描逻辑自动补全（如 `localPath`、`sourceType: 'localFs'`），用户可在「编辑描述」里再改。

## 四、编辑方式

1. **编辑描述（meta）**  
   - 列表选中组件 → 右侧「编辑」→ 表单编辑 type、componentName、分组、props 结构等。  
   - 保存时写回该组件目录下的 `meta.ts`。  
   - 与当前「组件库管理页面」的编辑面板一致，不依赖 Electron 以外的逻辑。

2. **编辑源码**  
   - 列表选中组件 → 提供「编辑源码」入口（如按钮或 Tab）。  
   - 打开该组件的**入口文件**（扫描时记录好的路径，如 `index.vue` 或 `src/Form.jsx`）内容，用简单文本/代码编辑器（如 textarea + 高亮，或后续接 Monaco）展示并编辑。  
   - 保存时通过 Electron 写回磁盘；可选：仅主入口一份，或后续支持多文件切换（先做单文件即可）。

这样：**选目录 → 自动分析 → 列表展示 → 无 meta 则询问是否生成 → 支持编辑描述 + 编辑源码**，与「组件库就约定成 packages 这样」的需求一致，Electron 只关心目录与文件读写，不关心项目内的 `packages/index` 注册逻辑。
